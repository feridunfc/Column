# Repository instructions — read before any task

## READ_BEFORE_WORK

Before planning, editing code, changing a test expectation, assigning a task,
or approving work in this repository:

1. Read this file and the **entire** canonical constitution:
   `docs/architecture/COLUMN_CONSTITUTION.md`.
2. Read the complete applicable task document:
   - Worker: `docs/tasks/COLUMN_WORKER_AB.md`.
   - Supervisor: `docs/tasks/COLUMN_SUPERVISOR.md`, plus the Worker task.
3. Run `python tools/check_architecture_contract.py` from the repository root.
4. Record the observed HEAD/tree, role, task, constitution version and SHA-256,
   task SHA-256, full-reading acknowledgment and the five rule explanations
   required by the task. A hash check does not replace reading.

Read-only repository identification, reading instructions and preparing the
bootstrap record are allowed before this sequence finishes. Do not begin
implementation, delegate implementation or approve a gate before it finishes.
If a document is missing, its version/hash differs, or instructions conflict,
stop the affected work and report the exact mismatch. Do not substitute an old
conversation summary, historical sprint prompt or architecture overview.

- Physical, analysis, design and result models remain separate and revisioned.
- Domain has no physics, external I/O, application or reporting imports.
- The new section path reaches the existing kernel only through its adapter.
- Numerical results, missing input and code compliance remain distinct.
- Source text or a digest is not an engineering qualification by itself.
- JSON and HTML project the same typed result; neither computes new physics.
- No live ETABS, analysis/design invocation or protected-model mutation in A/B.
- Preserve user changes, historical evidence, existing API and regression tests.

or their tests to make implementation drift pass. Do not skip/delete tests or

permission. Explicit current user instructions still apply and must be reflected
